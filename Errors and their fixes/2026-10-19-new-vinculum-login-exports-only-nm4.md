# New Vinculum login exports only warehouse NM4: Pick Pack / Order Enquiry files ~10x smaller

- **Date:** 2026-10-19
- **Reported as:** after VIN_LOGIN_ID was switched from the disabled user "Diwakar" to the new user's own login, the back-filled exports are ~10x smaller and hold ONE warehouse: `PickPackReport_15.10.2026` has every row `Source WH = NM4`; `OrderEnquiry_15-10-2026` has 36 orders vs ~300+/day before. "We want FULL reports for all warehouses without depending on the admin changing preferences, if the UI allows it."
- **Symptom:** rows per Source WH (probe Part A, run 39255914840, read-only Drive export of the Sheets):
  - `PickPackReport_08.10.2026` (old login): 1007 rows - NM7=194, NM1=183, N10=145, NM9=112, GJ1=97, AL4=77, A03=72, AL2=36, NM4=34, AL8=19, AL1=16, AL6=13, AL5=5, A06=4
  - `PickPackReport_09.10.2026` (old login): 849 rows - NM7=182, N10=152, NM1=151, NM9=110, GJ1=76, A03=50, AL6=46, A06=32, NM4=21, AL2=13, AL4=8, AL8=8
  - `PickPackReport_10.10.2026` (old login): 934 rows - NM7=168, NM1=142, N10=135, AL5=107, NM9=95, A03=83, GJ1=47, AL4=43, AL6=40, AL2=35, NM4=22, AL8=17
  - `PickPackReport_15.10.2026` (new login): 28 rows - NM4=28; `PickPackReport_17.10.2026` (new login): 56 rows - NM4=56
  - `OrderEnquiry_09-10-2026` (old login): 1078 orders; `OrderEnquiry_15-10-2026` (new login): 36 orders (the file has no location column; `Pickup Location` is blank in both).
- **Where:**
  - No script ever chose a location: `scripts/pickpack_report_to_drive.py`, `scripts/vinculum_sales_report_to_drive.py`, `scripts/order_enquiry_report_to_drive.py`, `scripts/inventory_report_to_drive.py` export whatever the session's location is.
  - Vinculum: after login the session sits on ONE location (`#orgLocKey = NM4_NASA`, header "Nasher Miles Pvt Ltd -AEPL"). The report screens' "Site Location" select offers only that location (Pick Pack `#siteLocationCode` name `loc`: `NM4` only; MIS/Sales `#siteLoc` name `reportDTO.siteLoc`: `NM4` only).
  - The header's asterisk icon "Switch Location" (`openSwitchDialog()` -> iframe `selCompanyLocationBS?operation=switch`, "User Preferences") has Company `NASA`, Location (17 options, no "All"): A02 BANGALORE3, A03 Kolkata Jalan Complex, A07 Gujarat GIDC, GJ1 Gujarat, NM0 Mumbai, NM2 IGL, NM1 VADAPE, NM4 AEPL (selected), S02 Orient (Abids), NM3 GLOBAL, S01 Palladium, NM6 GGN2, S03 Lakeshore Mall, NM8 Hyderabad, NM7 GGN1, NM9 Kol Aramex NM9, W03 Lakeshore Mall WH; radio Set As Default / Remove Default / Do Nothing (checked); Submit = `doCompanyChange()` -> POST `selectCompanyEretail`. The page's JS also knows a company value `**` (all companies, location disabled) that this user is not offered.
- **Root cause:** Vinculum exports only the session's current location. The old "Diwakar" user evidently had all-location access (its files hold 12-14 warehouses, including AL1, AL2, AL4, AL5, AL6, AL8, N10, A06); the new user is mapped to 17 locations, lands on NM4 and gets NM4 only. The scripts relied on the user's default and never switched location.
- **Why it wasn't caught:** nothing checks the size or warehouse spread of an export; a small file uploads "successfully" and the jobs stay green. The login change and the back-fill happened the same day.
- **Fix:**
  - `common/vinculum_ui.py`: `plan_locations` / `read_locations` read the Switch Location page; `resolve_locations` applies `VIN_LOCATIONS` (blank / `all` = every location the user can switch to; `A03,NM4` = those; `all,-S01,-S02` = all but those; an unknown code is an error, never skipped); `switch_location` selects the location, forces "Do Nothing" (the user's default location is never changed), calls the page's own `doCompanyChange()` and verifies the session location; `export_all_locations` runs one export per location (session location first, switches back at the end, logs rows per location, a retry reuses locations already exported for that date); `check_site_location` makes Pick Pack / Sales fail if the screen's Site Location is not the location just switched to; `session_lost` turns a mid-run logout into an immediate, explained failure.
  - `common/report_merge.py`: merges the per-location files into ONE file per date with the same name, file type, first sheet name (`Export`, `Sales Report`) and header; rows matched by column name; blank rows skipped; a row identical to one from an earlier location dropped; one file with data = that file unchanged. Pick Pack `Source WH` / Sales `Originating warehouse` still say where each row is from; Order Enquiry has no location column and none is added.
  - Pick Pack, Sales, Order Enquiry and Inventory use it (SKU Master is company master data, unchanged). A location with no data (Vinculum "No record/data found" message, Order Enquiry grid 0 orders, Inventory "No data found" on every search) contributes 0 rows; anything else that goes wrong fails the date - a partial merge is never uploaded.
  - Workflows: input `locations` (falls back to repo variable `VIN_LOCATIONS`), timeouts 350 min (Pick Pack, Sales, Order Enquiry) / 120 min (Inventory). `VIN_DRY_RUN=true` = export + merge without uploading; `vinculum-location-probe.yml` has `mode=probe` (read-only UI dump, `scripts/vinculum_location_probe.py`) and `mode=dry_run`.
  - `requirements.txt`: `openpyxl==3.1.5`, `et-xmlfile==2.0.0` (xlsx merge).
  - Tests: `tests/test_report_merge.py`, location tests in `tests/test_vinculum_ui.py` (74 pass).

  - Dry run 39258823030 (Pick Pack 15/10/2026, all 17 locations, no upload): NM4, A02, A03, A07, GJ1, NM0, NM2, NM1, S02, NM3 each switched (`[✓] Vinculum location is now A03`, `Site Location on screen: A03 (options: A03)`) and produced a SUCCESS PickPackReport (~50 s per location); then the session was logged out at NM3 and again in the retry (`URL: .../eRetailLogin.action`).

No other GitHub run was active; each login reported "You are already logged in from IP ... Do you really want to end previous session". Someone else is using this login at the same time.
