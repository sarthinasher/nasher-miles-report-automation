# GT orders from N10 / A06 / Head Office are in no Order Enquiry or Pick Pack file: the login cannot switch to those warehouses

- **Date:** 2026-10-23
- **Reported as:** "why is there a gap in 12th to 15th October in Full Flow FMS please check and fix that". While checking, the caller found GT121026A1's order N012271 (warehouse N10, ordered 2026-10-12 12:05, invoice 27/10/N10/1471) in the Sales file 13.10.2026 but in NO `OrderEnquiry_*` file, so Full Flow cannot stamp its punch date; likewise N012291 / N012292 (N10) and N461768 / N461774 / N461775 / N461783 / N461784 / N461787 (Head Office, N46 series).
- **Symptom:** the company-wide Sales file 13.10.2026 (828 rows) by `Originating warehouse` (caller's count): NM7 163, NM9 59, NM1 104, **N10 208**, A03 53, **A06 4**, GJ1 59, NM4 37, AL5 88, AL1 4, AL6 26, AL2 23. Pick Pack / Order Enquiry export only `LOCATIONS_WITH_ORDERS = A03,GJ1,NM1,NM4,NM7,NM9`.
- **Where:** `common/vinculum_ui.LOCATIONS_WITH_ORDERS` (Pick Pack / Order Enquiry default, 2026-10-21) and, underneath it, the Vinculum user's location mapping.
- **Root cause:**
  - N10, A06, AL1-AL8 and Head Office are NOT among the 17 locations this login can switch to. Every run logs the same list, e.g. 39797252301 (22-Oct): `Vinculum locations this user can switch to (17): A02, A03, A07, GJ1, NM0, NM2, NM1, NM4, S02, NM3, S01, NM6, S03, NM8, NM7, NM9, W03`. Order Enquiry and Pick Pack are per location, so those warehouses' orders cannot be exported by this user at all; no location list in the code can reach them. (Sales is company-wide, which is why N10 appears there.)
  - NM8 (Hyderabad, a GT route in the punch portal) is switchable but was left out of the 6-location default. It was a real 0, not an export problem: the 17-location Order Enquiry run 39264474236 switched to NM8 and read the grid on every date (`NM8: Order Enquiry grid shows 0 order(s) for 11/10/2026`, the same for 12-18/10), and Pick Pack 39394101857 / 39570271338 show `NM8=0` for 19/10 and 20/10.
- **Why it wasn't caught:** the 6-location default was built from the locations with rows in the 19/20-Oct runs, which can only show locations the user can switch to; nothing compared Order Enquiry against the company-wide Sales warehouses. The 2026-10-19 record lists AL1, AL2, AL4, AL5, AL6, AL8, N10, A06 as unreachable, but the GT impact (N10 is the biggest GT warehouse on 13/10) was not spelled out.
- **Fix:**
  - `LOCATIONS_WITH_ORDERS = "A03,GJ1,NM1,NM4,NM7,NM9,NM8,?N10,?A06"`: NM8 added; N10 and A06 are OPTIONAL (`?` prefix, new in `resolve_locations`): exported when the user can switch to them, otherwise each date logs `[!] NOT exported - this Vinculum user cannot switch to N10, A06: their orders are missing from the file until the admin maps the user to these locations.` A plain unknown code (no `?`) is still an error. Head Office is not added: its location code is unknown (the punch portal's `N46` is a channel/series code) and it is not switchable either.
  - Workflow `locations` descriptions updated (Pick Pack, Order Enquiry, Inventory).
  - Tests: `tests/test_vinculum_ui.py` - the default against the real 17-location list (7 exported), the default once N10 / A06 are mapped (9), optional-missing = warning, plain-missing = error.
- **Run budget:** measured per location per date incl. the switch: Pick Pack ~47 s (median 46 s, runs 39790158855 / 39570271338 / 39394101857), Order Enquiry ~63 s (median 62 s, 39797252301 / 39644816009 / 39618329909), plus ~1 min login per date. Default 7 locations: Pick Pack ~6.5 min per date, Order Enquiry ~8.5 min per date (12-date back-fill ~1 h 45 min). With N10 + A06 mapped (9): ~8 / ~10.5 min per date. All far below the 350-min timeout.
- **Blast radius:** every Order Enquiry / Pick Pack file since the login change (11-Oct onwards) misses N10, A06, AL* and Head Office orders; Full Flow FMS cannot stamp those GT orders (N012271, N012291, N012292, N461768, N461774, N461775, N461783, N461784, N461787 and more). A back-fill alone does NOT fix this.
- **Still open:**
  - The Vinculum admin must map the job's user to N10 and A06 (and Head Office, plus AL* if marketplace orders are needed) - or give it the old all-location access. Once mapped, the next runs export them automatically; then back-fill Order Enquiry 11/10/2026-22/10/2026 and Pick Pack for the same days, and re-run GT FMS Automation.
  - Find Head Office's location code (Switch Location list after the mapping) and add it to `LOCATIONS_WITH_ORDERS` (optional) if it is a separate location.
